Chainguard의 하드닝은 세 부품의 조합이다. 요리에 비유하면 이해가 빠르다.

🏔️

Wolfi

컨테이너 전용 리눅스(undistro). 군더더기 0, 커널 없음, 매일 보안 패치, 잘게 쪼갠 패키지. = 안전한 식재료 산지.

🏭

melange

소스 → 서명된 .apk 빌더. 격리 환경에서 빌드. Go 컴파일러 등 빌드 도구는 이 단계에만 존재. = 반조리 식품 공장.

🍽️

apko

패키지 → 이미지 조립기. Dockerfile/RUN 없이 선언한 패키지만 조립. SBOM 자동, 재현 가능. = 접시에 담기.

핵심: 빌드와 런타임을 분리한다. 컴파일러·셸·패키지매니저는 최종 이미지에 따라오지 않는다 → 공격 표면(=CVE)이 거의 0이 된다.

흐름 빌드 파이프라인

1
Go HTTP 서버표준 라이브러리만 쓰는 최소 앱 · / → "hello, hardened"
↓ make pkg
2
melange → hello-1.0.0-r0.apkWolfi 빌드환경에서 go/build · 자체 키로 패키지 서명
↓ make image
3
apko → harden:wolfi (8.94 MB)non-root(uid 65532) · entrypoint /usr/bin/hello · SBOM 자동 생성
↓ make sign
4
로컬 레지스트리 push + cosign 서명localhost:5050 push → digest 서명 → 검증
↓ make compare / verify
5
trivy·grype 스캔 + before/after 비교크기·CVE 표 출력 · cosign verify · SBOM 패키지 목록 확인

실행 make 한 줄로

# 전체 파이프라인: 빌드 → 패키지 → 이미지 → 서명 → 스캔 → 비교 → 검증
make all

# 단계별로도 실행 가능
make naive    # 비교용 무거운 golang 이미지
make pkg      # melange로 apk 빌드 (--privileged)
make image    # apko로 non-root 하드닝 이미지 + SBOM
make sign     # 로컬 레지스트리 push + cosign 서명
make compare  # 크기 + CVE 비교 표
make verify   # cosign verify + SBOM 목록

증거 정말 하드닝됐는가

① 셸이 없다 = 공격 표면 최소

docker run --rm --entrypoint /bin/sh harden:wolfi -c "echo hi"
→ exec: "/bin/sh": stat /bin/sh: no such file or directory  (정상)

② SBOM에는 선언한 패키지만 존재

# apko가 자동 생성한 SBOM
 - wolfi-baselayout 20230201-r29
 - ca-certificates-bundle 20260413-r0
 - hello 1.0.0-r0      # 우리 앱. 셸·컴파일러·패키지매니저 없음

③ 서명 검증 통과

Verification for localhost:5050/harden@sha256:c7cb1a1b... --
  - The cosign claims were validated
  - The signatures were verified against the specified public key

함정 이 머신에서 겪은 것들

🔑
cgr.dev credential helper 미설치

docker-credential-cgr가 설정만 되고 미설치 → 익명 pull 실패. 프로젝트 로컬 빈 config(.docker-anon/)를 DOCKER_CONFIG로 지정해 우회.

🔌
포트 5000은 macOS가 점유

AirPlay(ControlCenter)가 5000을 LISTEN 중 → 로컬 레지스트리를 5050으로 변경.

✍️
cosign v3 오프라인 서명

로컬 키 서명엔 투명성 로그(tlog)가 불필요. 서명은 --use-signing-config=false --tlog-upload=false, 검증은 --insecure-ignore-tlog로 진행(root 소유 ~/.sigstore 접근 회피).

🏷️
apko 로드 태그 / RepoDigest 정규화

apko 산출 tar는 harden:wolfi-arm64로 로드 → harden:wolfi로 재태그. RepoDigests[0]이 레지스트리 prefix 없는 값이라 localhost:5050/로 시작하는 digest만 필터링해 서명.
